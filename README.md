# TNDA 前導甄選 · 電子表單系統

紙本版本（`../Day1 表單組.dc.html`、`../Day2 表單組.dc.html`）維持不動，這裡是同一套表單的電子版：
**現場用手機填，資料直接進 Google 試算表，儀表板即時算出加權總分與個人回饋摘要。**

---

## 一、涵蓋哪些表單

| 表單 | 誰填 | 佔比 | 一張的單位 | 兩天共幾張 |
|---|---|---|---|---|
| D1 同儕評價單 | 學員 | 0%（訊號） | 每人一張、內含 14 列 | 30 張 · **420 列** |
| D1 選一位最想同組的人 | 學員 | 0%（分組用） | 每人一張 | 30 張 |
| D1 作品集答辯評分表 | 業師 | **55%** | 每位候選人一張 | 30–40 張 |
| D2 個人解題過程觀察表 | 業師 | **30%** | 每組每時段一張、逐人 | 20 張 · **60 列** |
| D2 業師回饋單 | 業師 | **15%** | 每組每題一張 | 20 張 |
| D2 自評與團隊內互評單 | 學員 | 0%（訊號） | 每人一張 | 30 張 · **90 列** |

**紙本兩天約 600 列要人工鍵入**，抓一列 20 秒也要 3 小時以上，而且：

- D1 的個人回饋摘要**當天 15:30 就要發**給候選人
- D2 的分組要用 D1 的互選資料，**當晚就得編**
- 55 / 30 / 15 的加權總分要在合議會議前算好，四位業師的分數還要能互相對照

這幾件事都撐不住事後鍵入，所以資料必須一產生就是結構化的。

**紙本仍然要印。** 每種各印 5 份備用（手機沒電、不想用手機、突發狀況）。
手抄的那幾張由工作人員用同一份表單代填即可，統計不受影響。

**為什麼不用 Google 表單。** 三個實際問題：

1. 同儕評價是在**每位同學發表完的 30–60 秒空檔**填一列，不是最後一次填完。
   Google 表單是線性題組，跳著填、回頭改都很痛苦。
2. 「理由最多勾 2 個」「一組只有這 3 個人」這種限制 Google 表單做不到，只能事後清理。
3. 回收是寬表（一位學員 42 欄），要先 unpivot 才能統計；業師端五份表單就是五張互不相干的試算表，
   加權總分還是得自己接。

## 二、檔案

| 檔案 | 用途 | 誰會碰 |
|---|---|---|
| **`config.js`** | **唯一要改的檔**：名單、分組、業師、題目、權重、時程、抽卡 | 你 |
| **`today.html?day=1｜2`** | **學員的 QR 落點**：當日行程 ＋ 每段要填的表單 | 學員 |
| **`run.html?day=1｜2`** | **業師的 QR 落點**：當日流程 ＋ 要做的事 ＋ 表單與收件數 | 業師、主辦 |
| `form.html?f=代號&day=N` | 通用表單引擎 | 學員、業師 |
| `draw.html` | **擂台賽上場順序**：按一下抽全場順序，投影用 | 主辦 |
| `dashboard.html` | 統計儀表板（含**編輯學生姓名**） | 主辦 |
| `index.html` / `staff.html` | 備援選單：掃錯 QR 或想看另一天時用 | 所有人 |
| `app.css` / `entry.css` / `app.js` | 共用樣式與執行期 | — |
| `apps-script.gs` | 貼進 Google Apps Script 的後端 | 你，一次 |

**填寫動線：掃 QR → 當日行程 → 點該時段的表單 → 填 → 送出 → 回當日行程。**
每一頁右上角都有「← 上一頁」；表單頁的上一頁就是它所屬那一天的行程表。

表單代號：`peer1` `pair1` `mentor1` `observe2` `team2` `self2`。

**同儕評價單與「選一位」是兩件事，不要搞混：**

| | D1 同儕評價單 `peer1` | D1 選一位最想同組的人 `pair1` |
|---|---|---|
| 何時填 | 每位同學結束後的換場 2 分鐘 | 17:00 頒獎後，一次填完 |
| 能選幾個 | **對同組 14 人各給一次「想／不想」，想幾個都可以** | **只能選一位** |
| 用途 | cohort 的合作意願基線、個人回饋摘要的素材 | Day 2 分組的硬配對 |

同儕評價的雙向「想一起做」會很多（一個人可能跟六七個人互相有意願），
所以**不能直接拿來編組**——它只是湊不出三人時的備援。真正決定分組的是「選一位」的互選。
全部不依賴任何外部函式庫，斷網也能開（只有字型會退回系統字型）。

**兩個入口是刻意分開的。** 學員入口只列出那兩張不計分的表與今天的流程；
業師入口有評分規準、權重（55/30/15）與儀表板連結，**不要把網址給學員**。
兩邊的抬頭顏色也不同（學員橘底、業師黑底），現場一眼分得出來拿錯頁面。

**流程頁也有兩版，讀的是同一份 `SCHEDULE`：**

| | `today.html`（學員） | `run.html`（業師與主辦） |
|---|---|---|
| 顯示 | 時間、內容、`you`（你這時候要做什麼） | 時間、內容、`todo`（那個時段要做的事） |
| 收件數字 | 沒有 | 有，每 2 分鐘自己更新 |
| 表單連結 | 沒有 | 有，每個時段直接連到該收的那份表單與該用的工具頁 |
| 其他操作 | 沒有 | 沒有 |

> **擂台賽抽籤**（`draw.html`）洗牌用 Fisher–Yates ＋ `crypto.getRandomValues`，
> 不是 `Math.random`——這是當眾抽的籤，要真的均勻也不能被算出來。
> 抽完存在那台裝置，重新整理不會跑掉；**重抽會再問一次**（當眾抽過的籤重抽會被質疑）。
> 也可以直接列印。

所以 `SCHEDULE` 的 `todo` 裡可以放催件、儀表板操作、業師差距門檻這類內部資訊，
**不會出現在學員那一頁**。要給學員看的話寫進 `you`。

**兩頁都是唯讀的行程表，都不標「現在」。** 行程會 delay、現場會滾動式調整，
不管是照時鐘自動標、還是叫人手動維護一個「現在」，都只是多一件會出錯、要顧的事。
兩頁的規則一樣：**是活動日就只列今天，不是的話兩天都列出來**，不用猜也不用切。
時程真的改了就改 `SCHEDULE` 的 `from` / `to`，重新上架。

業師版每個時段下面掛著那個時段該收的表單，**點下去就直接開那份表單**，
不用退回入口再找一次；後面的數字是收了幾份，收齊會變成橘底。
數字需要讀取金鑰，先到儀表板輸入一次，之後這台裝置上的 `run.html` 就會自己抓
（沒輸入的話最上面那一行會提示，連結與流程照樣可用）。

## 三、建置（約 40 分鐘，只做一次）

### 1 — 填 `config.js`

```
① ENDPOINT   先留空，第 2 步做完再回來貼
② PEOPLE     STUDENTS（一人一列：編號、Day1 組、Day2 組——**沒有姓名**）
             MENTORS（業師編號 ＋ days：他哪幾天出席）
③ FORMS      題目與權重，已照紙本填好，通常不用改
③-a CARDS    Day2 四副抽卡牌組（角色原型／招式限制／場景／互動限制）
             內容與代號對齊印刷牌組；業師回饋單是下拉選單，照代號選就好
③-b SCHEDULE 兩天的時程與每個時段要做的事——**日期一定要改成真實日期**
             `todo` 業師與主辦看得到；`you` 學員看得到；兩者不互通
④ SCORING    55 / 30 / 15，通常不用改
```

```js
const STUDENTS = [
  { id: '01', d1: 'A 組', d2: 'T01' },
  { id: '02', d1: 'A 組', d2: 'T02' },
  ...
];
```

**姓名不在這裡**——這個 repo 是公開的，真名放進原始碼等於把個資放上網。
姓名存在 Google 試算表，用儀表板的「名單」分頁輸入，見〈五-c〉。

**業師兩天不同人**，所以每位業師要標出席哪幾天：

```js
const MENTORS = [
  { id: 'M1', days: [1] },      // Day 1 五位
  …
  { id: 'M6', days: [2] },      // Day 2 另外幾位
  …
];
```

表單頁只會列出**那一天出席的業師**，不用在一長串裡找自己，也不會誤選成別天的人。
Day 1 的業師選過自己之後去開 Day 2 的表單，系統會要求重選（因為他不在 Day 2 的名單裡）。

**同一個人兩天都來就只給一個編號**、寫 `days: [1, 2]`——不要為了兩天開兩個編號，
那樣他在名單裡會出現兩次、改名也要改兩次。人數不同就自己加減行。

**系統靠 `id` 串六份表單，不靠姓名**——所以同名同姓不會被合成同一個人。
`id` 就用**名牌與桌牌上印的那個編號**（`../學員名牌.dc.html`、`../現場桌牌.dc.html`），
全場唯一、開始收資料後就不要再改（改了等於換一個人，已收的資料會對不上）。

姓名只負責顯示，可以重複。名單裡出現同名同姓時，畫面上會自動變成
`陳怡君（02）` 讓人分辨得出來；沒有重複的就顯示純姓名。

Day1 分組（`d1`）和 Day2 分組（`d2`）都是這一列的欄位，組別清單會自動推導出來。
**Day2 分組要 Day1 結束後才編得出來**，當天可以把 `d2` 整欄留成 `''`，
隔天填完存檔重新上架即可。

名單存檔後打開任一頁面，最上方若出現橘色警告，代表打字打錯了——
**編號重複**（兩個人會被當成同一個人）或**缺 Day1 組別**都會擋下來並指出是哪一列。
另外若出現黑底的「名單還沒載入」，代表試算表上還沒有姓名，見〈五-c〉。

### 2 — 建 Google 試算表後端

1. 新建試算表，命名「TNDA 前導甄選 評分資料」
2. **擴充功能 → Apps Script**，把 `apps-script.gs` 全部貼進去，存檔
3. **部署 → 新增部署作業 → 網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**任何人**（學員才不用登入 Google）
4. 複製 `https://script.google.com/macros/s/AKfy…/exec`
5. 用瀏覽器打開它，看到 `{"ok":true,…}` 就代表通了
6. 貼進 `config.js` 的 `ENDPOINT`
7. 把 `apps-script.gs` 最上面的 `READ_KEY` 換成**一串只有主辦知道的字**，重新部署新版本

> **`READ_KEY` 是什麼。** `/exec` 網址一定得是公開的（否則學員要先登入 Google），
> 所以「送出資料」不需要金鑰——但「把全部人的分數讀出來」需要。
> 金鑰只寫在 Apps Script 裡，**不會出現在任何上架的檔案**，
> 主辦第一次開儀表板時輸入一次，之後存在自己那台裝置。
> 沒有金鑰的人就算知道 `/exec` 網址、也開得了 `dashboard.html`，一樣讀不到資料。

系統會自動幫每份表單開一個分頁（`peer1`、`mentor1`…），欄位也自動建，
之後 `config.js` 加題目時**這支後端不用改**。

> 每次修改 `apps-script.gs` 後要「部署 → 管理部署作業 → 編輯 → 新版本」才會生效。

### 3 — 上架

已經上架在 **GitHub Pages**：<https://vgwtw.github.io/tnda-forms/>
（repo：<https://github.com/vgwtw/tnda-forms>）

改完東西要更新線上版：

```bash
git add -A && git commit -m "改了什麼" && git push
```

推上去約 1 分鐘後生效。**手機看到舊版就強制重新整理一次**（瀏覽器會快取 `config.js`）。

做**四個 QR Code**——角色 × 天數各一個：

| | 網址 | 印在哪／怎麼發 |
|---|---|---|
| 學員 Day 1 | `https://vgwtw.github.io/tnda-forms/today.html?day=1` | Day1 的學員名牌與現場桌牌 |
| 學員 Day 2 | `https://vgwtw.github.io/tnda-forms/today.html?day=2` | Day2 的桌牌（Day1 的名牌不要印這個，避免掃錯） |
| 業師 Day 1 | `https://vgwtw.github.io/tnda-forms/run.html?day=1` | 業師的校準速查卡，或直接傳給四位業師 |
| 業師 Day 2 | `https://vgwtw.github.io/tnda-forms/run.html?day=2` | 同上 |

> **這個 repo 是公開的，所以 `config.js` 裡沒有姓名。**
> 姓名存在 Google 試算表的 `roster` 分頁，各頁載入時才套用——
> 原始碼裡只有編號與分組，那不是個資。詳見〈五-c、輸入與修改姓名〉。

掃進去就是當天的行程，要填的表單直接從那一段點進去，**不用先找入口再找表單**。
掃錯天也沒關係，行程頁上有「看 DAY 2 的流程 →」可以切。

業師入口沒有做密碼——靜態網頁上的密碼擋不住任何人，加了只會給錯誤的安心感。
真正的保護在兩處：**評分資料要靠 `READ_KEY` 才讀得出來**，以及**試算表本身的存取權限**。
所以業師網址不用當機密文件保管，但也沒有理由印在學員看得到的地方。


### 4 — 事前測試（務必做）

1. 用手機掃 `today.html?day=1` 的 QR → 從行程裡點進同儕評價單 → 填幾列 → 送出
   （**送出前應該跳確認**，內容寫明送出後不能改）
2. 到試算表確認 `peer1` 分頁有資料
3. **再進同一張表單** → 應該顯示「這一張已經送出了」，進不去編輯畫面
4. 清掉那支手機的瀏覽器資料再送一次 → 後端應該回「先前已經送出過了」，**不會覆蓋**
5. 從 `run.html?day=1` 各填一份 `mentor1`；`run.html?day=2` 填 `observe2` / `team2`
6. 每一頁按右上角「← 上一頁」，確認都回得去
7. 開 `dashboard.html` → 貼上 `READ_KEY` → 「抓取最新資料」→ 看得到分數
8. 金鑰**故意打錯**再抓一次 → 應該出現「讀取金鑰不對」
9. 「名單」分頁改一個名字 → 儲存 → 用另一台裝置開學員行程，確認名字換了
10. 把手機開飛航模式再填一次 → 確認出現「匯出檔案」的離線路徑

## 四、現場流程

活動當天主辦與業師直接開 **`run.html`**（業師入口第一個連結），下面這兩張表就是它顯示的內容，
每個時段下面還會顯示那個時段該收的表單收了幾份。
學員那邊看的是 **`today.html`**——同一份時程，但只有時間與「你這時候要做什麼」。

> `SCHEDULE` 裡的 `date` 決定是只列今天還是兩天都列。
> 忘記改成真實日期不會壞掉，只是兩天都會列出來。

### Day 1

| 時間 | 動作 |
|---|---|
| 開場 | 業師先用**業師入口**（`/staff.html`）選好自己是誰；學員掃名牌上的 QR 進**學員入口**。兩邊都選完就不用再選。 |
| 發表開始前 | 口頭說明同儕評價：**匿名、不公開排行、不計入錄取分數**。請學員現在就打開入口頁、**照名牌上的編號**選好自己，**整場不要關掉分頁**。 |
| 每位答辯完 | 每人 15 分（答辯 8′／追問 5′／換場 2′）。學員換場那 2 分鐘填該同學那一列；業師填該候選人的評分表，**每個分數都寫證據**。 |
| 13:05 午休 | 「完成度」頁催件；「錄取總分」頁看**業師差距**欄——同一位候選人被兩位以上業師評時，差距 ≥ 1.5 就是要當場對分的邊界案例。 |
| 16:00–17:00 擂台賽 | 開 `draw.html` 按一下抽全場順序，**直接投影**。守擂制：第 01 位先上，贏的留台上、輸的換下一位。**不計分**，業師趁這段補齊評分表。 |
| 17:00 頒獎＋分組 | 頒完冠軍的小獎勵，請全員填「選一位最想同組的人」，**當場等它收齊**。 |
| 怎麼編 Day 2 分組 | 「D1 同儕訊號」頁 → 開主辦模式：<br>① **互選成功**的直接成組（每人只會出現一次）<br>② **還沒配到**的那張表，看「被選次數」與對方狀態牽線<br>③ 湊不出三人時，才看**備援的同儕雙向意願**（一人一列，白底＝還沒配到）<br>編好後填進 `config.js` 每一列的 `d2` 欄，存檔重新上架。 |
| 離場前 | 「個人回饋摘要」頁 →「產生全部文字」→ 當面發給每位候選人。 |

### Day 2

| 時間 | 動作 |
|---|---|
| 上午題結束 | 業師填 `observe2`（上午）與 `team2`（上午 · 角色招式）。 |
| 下午題結束 | 同上，時段/題目改成下午。 |
| 收尾 | 學員填 `self2`。 |
| 合議會議 | 儀表板「錄取總分」→「匯出」→ 下載總分表 CSV。 |

### 斷網怎麼辦

填答會存在該台裝置的瀏覽器裡，送出失敗**不會掉資料**，網路回來再按一次送出即可。
完全連不上時，畫面會出現「匯出檔案（CSV）」，存檔傳給工作人員，
工作人員在儀表板「載入資料」上傳即可（可一次選多個檔）。

前提是**頁面還開著**——所以第一步一定要請大家先打開、不要關。

## 五、儀表板怎麼讀

### 錄取總分

`D1 作品集答辯 55% + D2 個人過程觀察 30% + D2 團隊成果 15%`。
每個來源先把 1–5 的加權平均換算成 0–100，再加權。

- **已計入**：不是 100% 就代表那個人還缺表單。總分是拿現有部分重新歸一算的，
  **缺件補齊前不要拿來比較**。Day1 當天全部都會是 55%，這是正常的。
- **業師差距**：同一位候選人不同業師給的總分最大值減最小值。
  這是校準訊號，**≥ 1.5 就該在中場交叉校準時拿出來對**。
- 表格預設依姓名排序。點欄位標題可以排序，但排序只在這一頁，不是名次。

### D1 同儕訊號（0%）

合作意願分布附**組內中位數參考線**。刻意不做排名色階：這份表單向學員承諾「不公開排行」，
它要回答的是「這個 cohort 願不願意一起工作」。
分母是實際評到他的人數，14 人時**一票約 7 個百分點**，不要過度解讀小差距。

`G`（尚未看見足夠證據）佔比高 = **發表時間或位置的問題，不是這個人不好**。
處置方式是給他舞台、主動追問，不是扣分。

**Day 2 分組配對**（預設關閉，17:00 編組時才打開，不得對學員公布）分三層：

1. **互選成功** — 兩個人在「選一位」互相選到，直接成組。每人最多出現一次。
2. **還沒配到** — 一人一列，附「被選次數」「他選了誰」「對方的狀態」。
   被選次數高又還沒配到的人最好牽線。
3. **備援：同儕評價的雙向意願** — 一人一列，互選對象收在同一格（白底＝還沒配到、
   灰底＝已在別組）。因為一個人可能跟六七個人互相有意願，
   **這一層數量很大，只在湊不出三人時才看**。

### D2 過程與團隊

- 團隊成果兩題平均後套用到組內每一位，所以同組成員這一項分數相同。
- 個人過程觀察五個面向等權；同一人若有上下午兩張、多位觀察者，取平均。
- **自評 vs 隊友評**（0%）：差距為正代表自評高於隊友評。
  這一欄和 D1 的「自我認知與成長性」對照著看最有用，**±1.0 以上值得在合議時提出來**。
  差距本身不是缺點，**說不出理由才是**。

### 個人回饋摘要

每位候選人一張卡，橘框＝有需要業師主動處理的訊號（旗標、同儕曝光不足、自評落差大）。
「產生全部文字」會把分數、各面向證據、同儕原話、過程觀察、團隊下一步整理成純文字，
直接貼進紙本回饋單那一頁。

## 五-b、送出後不能修改

三道一起擋：

1. **送出前跳確認**，寫明送出後不能改；逐人的表單還會提醒「還有 N 位沒填」。
2. **前端上鎖**：送出成功後那一張就進不去編輯畫面，行程表上的按鈕變成「已送出」。
3. **後端擋重複**：同一把 `sid`（表單＋填答者＋抬頭的 key 欄位）已經有資料就直接回絕，
   **不會覆蓋舊資料**——換一台裝置重填也擋得住。

真的填錯要重填：到試算表把那個人的那幾列刪掉，他就能再送一次。
離線送出（沒設 `ENDPOINT` 或斷網）一樣只讓填一次，避免交回來兩份不同的檔案。

## 五-c、輸入與修改姓名

**姓名不在 `config.js` 裡，而在 Google 試算表的 `roster` 分頁。**
這個 repo 是公開的，真名放進原始碼等於把個資放上網；編號與分組不是個資，留在 code 裡沒問題。

### 活動前先建一次名單

1. 先做完第 2 步（Apps Script 部署、`ENDPOINT` 填好）
2. 開 `dashboard.html` →「名單」分頁 → 貼上 `READ_KEY`（在「載入資料」分頁）
3. **整批貼上**：從報名表的姓名欄複製一整欄貼進去，**一行一個、照編號順序**，
   按「填進表格」→ 對一下編號有沒有跑掉 → 「儲存到試算表」
4. 業師那四格自己打

之後要改名（打錯字、後來改名、想用大家平常叫的名字）都在同一頁改，
**所有裝置**下次開啟就會套用，不必重新上架網站。

### 還沒建名單會怎樣

各頁最上方會出現黑底提示「名單還沒載入，畫面上顯示的是編號」，
畫面上所有人名的位置一律顯示編號（`01`、`M1`…）。系統照常運作，只是難認人——
**所以一定要在學員報到前建好**。

### 只能改姓名，不能改編號

編號是所有資料的鍵——同儕評價、評分表、分組全部靠它串起來，改了等於換一個人。
要換人或調分組，還是要改 `config.js` 並重新上架。

姓名讀取不需要金鑰（名字本來就印在名牌上，學員端各頁都要讀得到），**寫入需要**。

## 六、資料與隱私

同儕評價與自評互評都向學員承諾匿名，所以：

- 試算表**限工作人員存取**，不要開「知道連結的人皆可檢視」
- 評分規準、權重與儀表板都在**業師入口**（`/staff.html`），學員入口看不到
- `READ_KEY` 只寫在 Apps Script 裡，不在任何上架的檔案中；儀表板輸入後只存在該台裝置
- 系統仍記錄填答者是誰（`submitter` 欄存編號，`submitter_name` 欄存姓名純粹是為了讓試算表好讀）——
  只用於**去重、催件、互選配對**三件事，不會出現在任何給學員看的畫面
- 儀表板「互選配對」預設關閉，是刻意的
- Apps Script 部署成「任何人」時，`/exec` 網址本身就是唯一的保護。
  **活動結束後請到「部署 → 管理部署作業」停用它**
- 業師評分含具體證據文字，屬於個人資料，匯出的 CSV 不要放在共用雲端硬碟的公開資料夾

## 七、要改題目時

全部在 `config.js` 的 `FORMS`。加一個面向：

```js
{ k: 'd_new', type: 'scale', label: '新面向', weight: 10, evidence: true }
```

`k` 是資料欄位名稱，**設定後不要再改**（改了等於換一欄，舊資料對不上）。
同樣的道理也適用於學員 `id`。
權重加起來不必是 100，系統會自己歸一，但寫成 100 比較好讀。
後端會自動在試算表右邊補上新欄位，既有資料不會位移。
